# keyring-winbridge v0.1.0

`v0.1.0` is the first public release of `keyring-winbridge`, a small Windows
helper that lets applications running inside WSL2 use Windows Credential
Manager.

## Highlights

- Introduces the versioned `keyring-winbridge/v1alpha1` JSON protocol over
  standard input and standard output.
- Supports `probe`, `get`, `set`, and idempotent `delete` operations.
- Stores arbitrary secret bytes as generic Windows credentials while keeping
  secrets out of command-line arguments and environment variables.
- Provides structured, machine-readable errors and defined process exit codes.
- Limits protocol messages to 1 MiB and decoded credential blobs to the
  2,560-byte Windows generic-credential limit.
- Reports the helper version and supported protocols through `probe`.

The helper is released independently from the `common.queueb.org/keyring` Go
library. The library does not download, install, or update the helper.

## Supported platform

The prebuilt `v0.1.0` executable targets `windows/amd64` with the
`GOAMD64=v1` baseline. The supported application scenario is a Linux process
inside WSL2 starting the helper through Windows executable interoperability.
The helper then operates in the Windows user context that started it.

WSL1, Windows on ARM, Wine, and environments without Windows executable
interoperability are not part of the tested `v0.1.0` support target.

## Installation

Download the prebuilt `keyring-winbridge.exe` from the assets attached to this
GitHub Release and place it where it can be executed by the intended Windows
user and from WSL2.

The executable can also be installed with the Go toolchain. Pin this release
for a reproducible installation:

```powershell
go install queueb.org/keyring-winbridge@v0.1.0
```

`go install queueb.org/keyring-winbridge@latest` is also supported. From WSL2,
cross-install the Windows executable explicitly:

```bash
GOOS=windows GOARCH=amd64 GOAMD64=v1 \
  go install queueb.org/keyring-winbridge@v0.1.0
```

With the default Go configuration, the cross-compiled executable is written
to `$(go env GOPATH)/bin/windows_amd64/keyring-winbridge.exe`. `GOBIN` must be
unset for a cross-install.

## Compatibility

The helper version and protocol version are independent. Clients must use
`probe` to verify support for `keyring-winbridge/v1alpha1` instead of inferring
protocol support from `v0.1.0`.

Before `1.0.0`, `0.MINOR` is the compatibility boundary. Patch releases in the
`0.1` line preserve the protocol set and semantics of `v0.1.0`; a later minor
release may introduce an incompatible contract under a new protocol
identifier.

The complete contract is documented in
[`docs/protocol/v1alpha1.md`](../protocol/v1alpha1.md), with runnable examples
in [`examples/README.md`](../../examples/README.md).

## Operational notes

- The helper operates in the Windows user context that starts it.
- Windows executable interoperability must be enabled when it is launched from
  WSL2.
- Each invocation handles exactly one request and then exits.
- Clients should start the executable directly without a shell, apply a short
  timeout, and treat transport or protocol failures as explicit errors.
- A bridge failure must not silently fall back to plaintext filesystem storage
  or a different secret backend.
